Current dashboard behavior:
  - Reads ClawdBot attack/action logs plus IDS audit logs.
  - Uses Chart.js from jsDelivr and Google Fonts from Google CDN.
  - Threat Velocity and Model Route charts are fixed-height Chart.js widgets.
  - Latest detections initially show 20 rows; use "Show more" for older rows.
  - "Open" on an incident shows MITRE mapping, response actions, model route, confidence, firewall action, and reputation enrichment.
  - Telegram-signaled primary attacks create a top-right dashboard popup.
  - Dashboard popups are only for primary attacks, not secondary context.
  - Threat counts are incident-based: one primary threat plus X possible secondary labels, not raw flow count.
  - Management/dashboard traffic on ports 22, 64295, 5000, 8000 is hidden by default.

Browser note:
  After dashboard CSS/JS changes, hard-refresh Chrome with Cmd+Shift+R.

11. LORA FINE-TUNING (triage model)
------------------------------------------------------

# All commands run on SVM with venv activated:
source /data/ton-iot-project/venv_h200/bin/activate
cd /data/ton-iot-project/fresh_start

# Step 0: Install training dependencies (one-time)
pip install -r lora/requirements.txt

# Step 1: Generate synthetic training data
python -m lora.build_dataset \
  --out data/triage_train.jsonl \
  --test-out data/triage_test.jsonl \
  --n-per-class 50

# Step 2: Train QLoRA adapter (~15-30 min on H200)
python -m lora.train \
  --dataset data/triage_train.jsonl \
  --output lora_adapter \
  --epochs 3

# Step 3: Export to Ollama
python -m lora.export_ollama \
  --adapter lora_adapter \
  --model-name clawdbot-triage \
  --quantization q8_0

# Step 4: Evaluate against base model
python -m lora.evaluate \
  --test-data data/triage_test.jsonl \
  --base-model mistral-small:24b \
  --tuned-model clawdbot-triage

# Step 5: Switch agent to use fine-tuned model
# Edit /etc/systemd/system/ids-api.service:
#   Environment="OLLAMA_MODEL_TIER1=clawdbot-triage"
# Then:
sudo systemctl daemon-reload
sudo systemctl restart ids-api clawdbot-agent

# Verify Ollama sees the new model
ollama list | grep clawdbot-triage

12. TROUBLESHOOTING
------------------------------------------------------

Problem: "timed out" errors in clawdbot-agent logs
  → Check if Ollama is running: sudo systemctl status ollama
  → Check if models are loaded: ollama list
  → Restart Ollama: sudo systemctl restart ollama

Problem: Everything classified as "normal"
  → Verify model artifacts: ls /data/ton-iot-project/fresh_start/artifacts/resnet_transfer/
  → Check capture interface is correct: grep INTERFACE /etc/systemd/system/clawdbot-agent.service

Problem: No flows captured
  → Check interface exists: ip link show wt0
  → Make sure NetBird VPN is connected: netbird status

Problem: Telegram alerts not sent
  → Check .env has TELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID
  → Test manually: curl -s "https://api.telegram.org/bot<TOKEN>/sendMessage?chat_id=<CHAT_ID>&text=test"

Problem: Dashboard not loading or charts look broken
  → Restart dashboard: sudo systemctl restart ids-dashboard
  → Check logs: sudo journalctl -u ids-dashboard -b --no-pager
  → Verify health: curl -s http://127.0.0.1:5000/health | python3 -m json.tool
  → Hard-refresh Chrome with Cmd+Shift+R after CSS/JS deployments
  → Confirm internet access for Chart.js/Google Fonts CDNs

Problem: Dashboard shows scanning caused by dashboard browsing
  → Confirm ports 5000/8000 are ignored: grep TON_IOT_DASHBOARD_IGNORE_PORTS /etc/systemd/system/ids-dashboard.service
  → Confirm ClawdBot management ports include 5000/8000 in logs
  → Restart both services: sudo systemctl restart clawdbot-agent ids-dashboard

Problem: Service won't start
  → Check for syntax errors: sudo systemctl status ids-api
  → Check full logs: sudo journalctl -u ids-api -b --no-pager
